# Questions Authoring Guide

Правила создания и изменения вопросов в сборнике «Вопросы с собеседований».

## Структура

```
questions/
  <направление>/              # frontend, backend, devops, hr
    meta.json                 # заголовок, описание, порядок
    <технология>/             # javascript, react, go, kubernetes...
      meta.json               # заголовок, описание, порядок
      chapters/
        NNN-slug.md           # глава с вопросами
```

Особый случай — направление `hr`: у него нет технологий, главы лежат напрямую
в `questions/hr/chapters/`.

## ID

- Направление: `frontend`
- Технология: `frontend/javascript` (путь от `questions/`)
- Глава: `frontend/javascript/003-async-event-loop`
- Вопрос: `frontend/javascript/003-async-event-loop/002` (порядковый номер)

## meta.json

Направление:

```json
{
  "title": "Frontend",
  "description": "Разработка интерфейсов: JavaScript, TypeScript, React, HTML и CSS",
  "order": 1
}
```

Технология:

```json
{
  "title": "JavaScript",
  "description": "Язык веба: типы, замыкания, асинхронность, прототипы",
  "order": 1
}
```

`order` — сортировка внутри родителя. У hr `order` = позиция среди всех направлений.

## Формат главы (chapters/NNN-slug.md)

```markdown
# Название главы

## Текст вопроса?

Ответ на вопрос в markdown — 3-7 предложений, как сильный ответ
на техсобеседовании: сначала суть, потом детали.

## Второй вопрос?

Второй ответ.
```

Правила:

- Первая строка — `# Название главы`
- Каждый вопрос — заголовок `## ...`, обычно заканчивается на `?`
- **В ответах запрещены заголовки `#` и `##` вне блоков кода** — они
  зарезервированы парсером (внутри ```-блоков комментарии `#` допустимы)
- В ответах разрешены: блоки кода, `инлайн-код`, **жирный**, списки
- Язык — русский
- 7-9 вопросов на главу — целевой объём
- Имя файла: `NNN-slug.md`, NNN — следующий свободный номер, slug — kebab-case

## Как работает система

1. **Scanner** (`src/lib/questions-scanner.ts`) обходит `questions/`,
   парсит главы, кеширует (2с в dev, бесконечно в production).
2. **API** `GET /api/questions` отдаёт полное дерево (dev-режим).
3. **Build** (`scripts/build-questions.mjs`) пишет `public/questions.json`
   для статической сборки (GitHub Pages).
4. **UI** — страницы `/questions` (направления + поиск),
   `/questions/[direction]` (технологии), `/questions/[direction]/[technology]`
   (главы с аккордеоном вопросов + локальный поиск).

## Добавление вопроса

### Через UI (автоматически)

Кнопка «➕ Добавить вопрос» открывает предзаполненный GitHub Issue.
Workflow `Generate Question from Issue` (.github/workflows/new-question.yml)
срабатывает автоматически: LLM определяет главу, пишет ответ → вопрос
дописывается в главу → черновик Pull Request.

### Вручную

1. Найдите главу по смыслу в `questions/<направление>/<технология>/chapters/`
2. Допишите в конец файла:

```markdown

## Новый вопрос?

Ответ.
```

3. Если нужна новая глава — создайте `chapters/NNN-slug.md` с `# Название`
4. Если нужна новая технология — создайте папку с `meta.json` + `chapters/`

## Валидация

```bash
npm run validate:questions
```

Проверяет: meta.json у всех узлов, `#`-заголовок глав, непустые ответы,
отсутствие запрещённых заголовков в ответах, kebab-case имён.

## Что ЗАПРЕЩЕНО

- Заголовки `#`/`##` в ответах вне код-блоков (ломают парсер)
- Менять формат глав — он захардкожен в сканере, билдере, валидаторе
  и генераторе (четыре места синхронно)
- Дублировать вопросы внутри технологии
- Создавать направления без веской причины (frontend/backend/devops/hr
  — зафиксированный набор)
