# Основы типизации

## Зачем нужен TypeScript и что он даёт?

TypeScript — это JavaScript со статической типизацией: ошибки типов ловятся на этапе компиляции, а не в рантайме. Плюсы: автодополнение и навигация по коду, самодокументирующиеся API, безопасный рефакторинг, меньше багов в границах модулей.

```ts
function sum(a: number, b: number): number {
  return a + b;
}
sum("1", 2); // ошибка компиляции, а не NaN в проде
```

TS компилируется в обычный JS и полностью исчезает в рантайме — типы существуют только при разработке.

## Чем type отличается от interface?

Оба описывают форму объекта. `interface` — только объектные типы, поддерживает declaration merging (авто-расширение при повторном объявлении). `type` — всё что угодно: объединения, пересечения, примитивы, mapped-типы, кортежи.

```ts
interface User { name: string }
interface User { age: number } // User теперь имеет оба поля

type ID = string | number;    // union — только type
type Pair = [string, number]; // кортеж
```

Практика: `interface` для публичных API объектов (расширяемость), `type` для остальных случаев. На поведение программы разница не влияет.

## Что такое union и intersection типы?

Union (`A | B`) — значение одного из типов: «или». Intersection (`A & B`) — значение удовлетворяет всем типам сразу: «и».

```ts
type Status = "idle" | "loading" | "error";  // конкретное одно из
type Admin = User & { permissions: string[] }; // User И permissions
```

Union с литеральными типами заменяет enum в большинстве случаев и отлично сужается через `switch`.

## Что такое literal types и когда они полезны?

Тип, допускающий ровно одно значение: `let x: "on" | "off"`. В комбинации с union дают выразительные состояния без enum.

```ts
type Method = "GET" | "POST" | "DELETE";
function request(method: Method) { /* ... */ }
request("PUT"); // ошибка — опечатка поймана
```

Литеральные типы — основа discriminared unions: `"error"` как дискриминант позволяет тайпчекеру понять, какой вариант объединения перед ним.

## Чем enum отличается от const enum и union литералов?

`enum` создаёт реальный объект в рантайме (двусторонний маппинг имя↔значение). `const enum` полностью разворачивается на этапе компиляции. Union литералов — вообще без рантайма, только типы.

```ts
enum Color { Red, Green }        // объект в JS-выхлопе
const enum C2 { Red }            // inline, объекта нет
type Color3 = "red" | "green";   // чистый тип
```

Современный консенсус: для строковых наборов — union литералов (нулевая цена, tree-shake friendly); `enum` оправдан для числовых наборов или обратного маппинга.

## Чем any отличается от unknown и never?

`any` — отключение проверки типов (в обе стороны: что угодно присвоить и как угодно использовать). `unknown` — «не знаем, что», безопасная версия: присвоить можно, использовать — только после сужения. `never` — «значения не существует»: недостижимый код, пустое множество.

```ts
let a: any = fetch(); a.foo.bar;     // компилируется, падает в рантайме
let u: unknown = fetch(); u.foo;     // ошибка — сначала сузить
function fail(): never { throw new Error(); }
```

Правило: `any` — временный костыль; `unknown` — честный тип для внешних данных; `never` — для исчерпывающих проверок switch.

## Что такое структурная типизация?

Совместимость типов определяется формой, а не именем: если у объекта есть все требуемые поля нужных типов — он подходит. Это «утиная типизация» на этапе компиляции.

```ts
interface Point { x: number; y: number }
const p = { x: 1, y: 2, z: 3 };
const point: Point = p; // ок — есть x и y, лишнее не мешает
```

Следствие — «freshness» проверка литералов: избыточные свойства в литерале прямо при присваивании дают ошибку excess property check, но не при передаче через переменную.

## Как типизировать функции: перегрузки и optional/ default параметры?

Опциональные параметры — `?`, дефолты — `=`. Перегрузки задают несколько сигнатур одной функции.

```ts
function parse(input: string): Date;
function parse(input: number): Date;
function parse(input: string | number): Date {
  return new Date(input);
}
parse("2024-01-01"); // возвращает Date — сигнатура 1
```

В реализации обязана быть максимально широкая сигнатура. Перегрузки полезны для API вроде `createElement(tag)`, где набор аргументов зависит от первого параметра.
