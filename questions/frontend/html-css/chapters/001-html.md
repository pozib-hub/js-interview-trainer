# HTML и семантика

## Зачем нужна семантическая разметка?

Семантические теги (`header`, `nav`, `main`, `article`, `section`, `footer`) описывают смысл содержимого, а не внешний вид. Это даёт доступность (скринридеры навигируют по landmark-ролям), SEO (поисковики понимают структуру) и читаемость кода.

```html
<body>
  <header><nav>…</nav></header>
  <main>
    <article>…</article>
  </main>
  <footer>…</footer>
</body>
```

`<div>` и `<span>` — только когда нет подходящего смыслового тега, а не по умолчанию.

## Чем article отличается от section?

`article` — самодостаточная единица, имеющая смысл вне страницы: пост, комментарий, карточка товара. `section` — тематическая группа внутри документа, обычно с заголовком.

```html
<article>              <!-- пост в блоге — сам по себе цельный -->
  <h1>Заголовок поста</h1>
  <section><h2>Вступление</h2>…</section>
  <section><h2>Код</h2>…</section>
</article>
```

Тест на `article`: можно ли вырезать и опубликовать отдельно в RSS — да, значит article.

## Чем отличаются defer и async у скриптов?

Оба загружают скрипт параллельно с парсингом HTML. `defer` выполняется после полного парсинга, в порядке следования; `async` — сразу по загрузке, порядок не гарантирован.

```html
<script src="lib.js" defer></script>  <!-- порядок сохранён, DOM готов -->
<script src="analytics.js" async></script> <!-- независимый трекер -->
```

`defer` — для скриптов, зависящих от DOM и друг от друга; `async` — для независимых (аналитика, A/B). Скрипт без атрибутов блокирует парсинг.

## Что делает атрибут alt и когда он не нужен?

`alt` — текстовая альтернатива изображения: показывается при ошибке загрузки, читается скринридером, индексируется поисковиками. Обязателен у всех `<img>`; пустой `alt=""` — если картинка чисто декоративная.

```html
<img src="chart.png" alt="Продажи по кварталам: рост с 12 до 48 млн">
<img src="divider.svg" alt=""> <!-- декор — пустой alt -->
```

Хороший alt описывает смысл, а не файл: не «фото собаки.jpg», а «спасатель с собакой на фоне гор».

## Какие мета-теги важны для страницы?

`viewport` — управление масштабом на мобильных; `charset` — кодировка; `description` — сниппет в поиске; Open Graph — превью в соцсетях.

```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="description" content="Тренажёр для подготовки к собеседованиям">
<meta property="og:title" content="Interview Trainer">
```

Без `viewport` мобильные браузеры рисуют десктопную версию шириной 980px и масштабируют — «мобильность» пропадает.

## Чем блочные элементы отличаются от строчных?

Блочные (`div`, `p`, `h1`) начинаются с новой строки, занимают всю доступную ширину, могут содержать блочные и строчные. Строчные (`span`, `a`, `strong`) идут в потоке текста, width/height сверху не работают.

```html
<p>Текст с <a href="#">ссылкой</a> и <strong>выделением</strong>.</p>
```

Есть промежуточные `inline-block` (в строке, но размеры задаются) и современные `flex`/`grid`-контейнеры, которые меняют модель детей напрочь.

## Что такое data-атрибуты и когда их использовать?

`data-*` — способ хранить произвольные данные прямо в разметке, читаемые из JS через `dataset` и в CSS как атрибуты.

```html
<button data-action="copy" data-id="42">Копировать</button>

<script>
  btn.dataset.action; // "copy"
</script>
```

Уместны для передачи конфигурации в виджеты; не место для сериализованных больших объектов — это всё ещё разметка, её читают люди и парсеры.

## Что такое доступность (a11y) на базовом уровне?

Практика делать интерфейс usable для всех: клавиатурная навигация, семантика, контраст, alt, focus-менеджмент. Минимум в разметке: правильные теги, `label` у полей, `aria-*` там, где семантики не хватает.

```html
<label for="email">Email</label>
<input id="email" type="email" required>

<button aria-expanded="false" aria-controls="menu">Меню</button>
```

Первое правило ARIA — не использовать ARIA: нативный `<button>` уже доступен, `<div onclick>` — нет, и `role="button"` лишь частично чинит.
