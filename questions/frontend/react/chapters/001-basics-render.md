# Основы и рендер

## Что такое React и какие у него ключевые идеи?

React — библиотека для построения UI на компонентах. Три кита: декларативность (описываем «как должен выглядеть результат», а не мутируем DOM), компонентность (композиция из мелких переиспользуемых единиц), однонаправленный поток данных (данные текут сверху вниз через props).

```tsx
function Greeting({ name }: { name: string }) {
  return <h1>Привет, {name}!</h1>;
}
```

React описывает слой View; состояние и данные — забота приложения (контекст, сторы, серверные кеши).

## Что такое JSX и во что он компилируется?

JSX — синтаксический сахар: `<div>Привет</div>` превращается в вызов `React.createElement` (или автоматический `jsx(...)`) — создается объект-описание элемента.

```tsx
// JSX
<Greeting name="Аня" />

// примерно так:
React.createElement(Greeting, { name: "Аня" })
// → { type: Greeting, props: { name: "Аня" } }
```

JSX — выражения JavaScript: можно класть в переменные, возвращать из условий, собирать в массивы. Это не HTML: `className` вместо `class`, `{выражения}` вместо директив.

## Что такое виртуальный DOM и reconciliation?

Виртуальный DOM — легковесное JS-описание дерева UI. React хранит два снимка (текущий и новый), сравнивает их (reconciliation) и применяет к реальному DOM только минимальный набор изменений.

```tsx
// состояние изменилось: counter 1 → 2
<span>{counter}</span>
// React обновит только текстовый узел span, не пересоздавая DOM-дерево
```

Цель — работать с DOM декларативно, но не платить полную цену перерисовки. Сравнение идёт по типам элементов и ключам.

## Зачем React нужны keys в списках?

`key` — стабильная идентичность элемента списка между рендерами. По ключам React понимает: это тот же элемент (обновить), а не новый (создать) или удалённый (убрать).

```tsx
{items.map((item) => (
  <ListItem key={item.id} data={item} />
))}
```

Индекс как key — проблема при вставках/удалениях/сортировке: элементы «перепутываются», внутреннее состояние (input, анимации) переезжает не туда. Ключ должен быть уникален среди соседей и постоянен.

## Чем отличаются управляемые и неуправляемые компоненты?

Управляемый: значение поля живёт в state, React — источник истины. Неуправляемый: значение живёт в DOM, читается по требованию (ref).

```tsx
// Управляемый
<input value={value} onChange={(e) => setValue(e.target.value)} />

// Неуправляемый
const inputRef = useRef<HTMLInputElement>(null);
<input ref={inputRef} defaultValue="начальное" />
```

Управляемые — для валидации и связанных полей, неуправляемые — для простых форм и `<file input>`, где управляемость невозможна.

## Что делает StrictMode и почему в dev всё рендерится дважды?

`<StrictMode>` включает дополнительные проверки разработки: двойной вызов рендер-функций и эффектов, чтобы выявить нестабильный код и побочные эффекты в рендере.

```tsx
<React.StrictMode>
  <App />
</React.StrictMode>
```

Двойной вызов — не баг, а детектор: если результат меняется между вызовами, код хрупкий. На production-сборку StrictMode не влияет. Правильная реакция — убрать побочки из рендера, а не отключить режим.

## Чем SSR отличается от CSR и что такое гидрация?

CSR (client-side rendering): браузер получает пустой HTML и рисует всё на клиенте. SSR (server-side): сервер отдаёт готовый HTML, React «гидратирует» его — attaching обработчиков и state на уже существующую разметку.

```tsx
// Next.js App Router: компонент по умолчанию серверный,
// "use client" — точка перехода к клиентскому коду
```

SSR быстрее показывает первый экран и лучше для SEO; гидрация требует, чтобы серверный и клиентский рендер совпали — иначе warning о mismatch.

## Чем компонент отличается от элемента?

Элемент — immutable-объект-описание: `{ type, props }`. Компонент — функция или класс, принимающий props и возвращающий элементы. Элемент «ссылается» на компонент через `type`.

```tsx
const element = <Greeting name="Аня" />; // элемент — описание
function Greeting(props) { return <h1>…</h1>; } // компонент — фабрика
```

Отсюда правило: рендер-функция создаёт новые элементы при каждом рендере, но React переиспользует компоненты — это дёшево.
