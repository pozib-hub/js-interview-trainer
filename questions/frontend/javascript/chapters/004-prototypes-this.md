# Прототипы, this и классы

## Как работает прототипное наследование?

У каждого объекта есть скрытая ссылка `[[Prototype]]` на объект-прототип. При чтении свойства движок ищет его в самом объекте, затем по цепочке прототипов до `null`. Запись же почти всегда создаёт свойство прямо на объекте.

```ts
const animal = { eats: true };
const rabbit = { jumps: true, __proto__: animal };
rabbit.eats; // true — нашли в animal
```

Так достигается переиспользование без классов: методы лежат на прототипе один раз, а не копируются в каждый экземпляр.

## Чем `__proto__` отличается от `prototype`?

`obj.__proto__` — геттер/сеттер ссылки `[[Prototype]]` конкретного объекта (устаревший, но поддерживается). `Constructor.prototype` — свойство функции-конструктора: объект, который станет прототипом для экземпляров, созданных через `new`.

```ts
function User() {}
User.prototype.sayHi = function () {};
new User().__proto__ === User.prototype; // true
```

Связь: `instance.__proto__ === Constructor.prototype`. Проверка `instanceof` идёт по цепочке прототипов конструктора.

## Как работает `this` и от чего зависит?

Значение `this` определяется в момент вызова, а не объявления. Правила по приоритету: `new` → новый объект; `call/apply/bind` → явно переданный; метод объекта → сам объект; обычный вызов → `undefined` (strict) или `globalThis`.

```ts
const user = { name: "Аня", hi() { console.log(this.name); } };
user.hi();                 // "Аня"
const hi = user.hi;
hi();                      // undefined — потеряли контекст
```

Потеря `this` при передаче метода как колбэка — классический источник багов; лечится `bind` или стрелочной обёрткой.

## Чем стрелочные функции отличаются от обычных?

Стрелочные функции не имеют собственного `this`, `arguments` и не могут быть конструкторами: `this` берётся лексически из внешней области. Они короче и идеальны для колбэков, где нужен внешний контекст.

```ts
function Timer() {
  this.seconds = 0;
  setInterval(() => this.seconds++, 1000); // this — экземпляр
}
```

В методах объектов стрелки использовать не стоит — `this` не будет указывать на объект. Там лучше обычные методы или короткий синтаксис `hi() {}`.

## Что делают call, apply и bind?

Это способы явно задать `this`. `call` и `apply` вызывают функцию сразу (разница — формат аргументов: список против массива), `bind` возвращает новую функцию с навсегда привязанным контекстом без вызова.

```ts
function greet(greeting) { return `${greeting}, ${this.name}`; }
const user = { name: "Иван" };

greet.call(user, "Привет");   // "Привет, Иван"
greet.apply(user, ["Привет"]); // то же
const bound = greet.bind(user);
bound("Привет");              // "Привет, Иван"
```

Полифил `bind` — частое задание на собеседовании: замыкание + `apply`.

## Что такое классы в JavaScript?

`class` — синтаксический сахар над прототипным наследованием. Внутри всё та же цепочка `[[Prototype]]`, но синтаксис читабельнее: конструктор, методы на прототипе, статические методы, `extends`/`super`, приватные поля `#`.

```ts
class Animal {
  #secret = "hidden";
  constructor(name) { this.name = name; }
  speak() { return `${this.name} говорит`; }
  static kind() { return "животное"; }
}
class Dog extends Animal {
  speak() { return super.speak() + ": гав"; }
}
```

Ключевое отличие от функций: классы не поднимаются (hoisting) и всегда работают в strict mode.

## Что такое приватные поля и getters/setters?

Приватные поля (`#field`) доступны только внутри класса извне — попытка доступа извне даёт синтаксическую ошибку. Геттеры/сеттеры — свойства с вычислением: `get` возвращает значение, `set` валидирует и присваивает.

```ts
class User {
  #email;
  get email() { return this.#email; }
  set email(v) {
    if (!v.includes("@")) throw new Error("Некорректный email");
    this.#email = v;
  }
}
```

Геттер позволяет держать инварианты (валидность данных) внутри класса, не разбрасывая проверки по коду.

## Как создать объект без прототипа?

`Object.create(null)` создаёт «чистый» объект без цепочки прототипов — у него нет даже `toString`. Полезно для словарей: ключи-строки вроде `toString` или `constructor` не конфликтуют с унаследованными свойствами.

```ts
const dict = Object.create(null);
dict.toString = 1; // безопасно — просто ключ
```

Обычный объект-словарь `{}` лучше создавать через `Object.create(null)` или `Map`, если ключи приходят извне и могут совпасть с прототипными именами.
