# Замыкания и область видимости

## Что такое замыкание?

Замыкание — это функция вместе с лексическим окружением, из которого она была создана. Внутренняя функция сохраняет доступ к переменным внешней даже после того, как внешняя функция завершилась.

```ts
function counter() {
  let count = 0;
  return () => ++count;
}
const next = counter();
next(); // 1
next(); // 2
```

Благодаря замыканиям работают модули, каррирование, приватное состояние и обработчики событий с «запомненными» данными.

## Что такое лексическая область видимости?

Область видимости определяется в момент написания кода по физическому расположению символов, а не в момент вызова. Функция ищет переменные там, где она объявлена, затем во внешних областях — вплоть до глобальной.

```ts
const x = "outer";
function f() {
  console.log(x); // "outer" — берётся из места объявления
}
```

Именно лексика делает замыкания предсказуемыми: неважно, откуда вызвали функцию, — важно, где она написана.

## Что такое hoisting (всплытие)?

Объявления `var` и функций поднимаются наверх области видимости: функции — целиком (можно вызвать до объявления), `var` — только декларация со значением `undefined`. `let`/`const` тоже поднимаются, но попадают во временную мёртвую зону (TDZ).

```ts
sayHi(); // работает — function declaration всплыла
function sayHi() {}

console.log(v); // undefined
var v = 1;
```

Хостинг объясняет классическую ловушку: цикл `for (var i...)` с колбэками выводит одно и то же значение `i` для всех итераций.

## Что такое временная мёртвая зона (TDZ)?

Это период между входом в блок и выполнением строки объявления `let`/`const`. Обращение к переменной в этот момент даёт `ReferenceError`, а не `undefined`.

```ts
{
  console.log(a); // ReferenceError: Cannot access 'a' before initialization
  let a = 1;
}
```

TDZ защищает от использования переменной до её инициализации и делает ошибки явными — одно из преимуществ `let` перед `var`.

## Почему в цикле с `var` колбэки видят одно значение?

`var` имеет функциональную область видимости: для всех итераций создаётся одна переменная. К моменту срабатывания `setTimeout` цикл уже завершился, и все замыкания ссылаются на финальное значение.

```ts
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3, 3, 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0, 1, 2
```

`let` на каждой итерации создаёт новую переменную, поэтому замыкания захватывают разные значения. То же самое можно добиться через IIFE с параметром.

## Что такое IIFE и зачем оно нужно?

Immediately Invoked Function Expression — функция, которая объявляется и тут же вызывается: `(function () { ... })()`. Классический способ создать изолированную область видимости до появления `let`/`const` и модулей.

```ts
const module = (function () {
  let private = 0;
  return { inc: () => ++private };
})();
```

Сейчас IIFE встречается реже — ES-модули и блочная область видимости закрывают большинство сценариев, но паттерн всё ещё полезен для изоляции и асинхронных entry-point.

## Как замыкания могут приводить к утечкам памяти?

Если долгоживущий объект (например, глобальный обработчик или кеш) держит ссылку на функцию, а она через замыкание — на крупные внешние данные, то эти данные не соберутся сборщиком мусора, хотя реально уже не нужны.

```ts
function attach(el) {
  const bigData = new Array(1e6).fill("x");
  el.addEventListener("click", () => render(bigData));
}
```

Решения: ослаблять ссылки (обнулять), удалять слушатели, не захватывать в замыкание больше, чем нужно, выносить большие данные наружу.

## Что выведет сравнение объектов и почему?

```ts
const a = { x: 1 };
const b = { x: 1 };
a == b;  // false
a === b; // false
```

Оба сравнения `false`, потому что сравниваются ссылки, а не содержимое. Это ключевой повод для глубокого сравнения: `structuredClone` для копий и специализированные `isEqual`-утилиты или сравнение по идентификатору для проверки равенства.
