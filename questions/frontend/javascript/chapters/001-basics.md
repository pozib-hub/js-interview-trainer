# Основы и типы

## Какие типы данных есть в JavaScript?

Восемь: семь примитивных — `number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint` — и один структурный: `object`. Примитивы хранятся по значению и иммутабельны, объекты — по ссылке.

```ts
typeof 1;        // "number"
typeof "a";      // "string"
typeof null;     // "object" — исторический баг языка
typeof (() => {}); // "function" — подпадает под object
```

`typeof null === "object"` — известная ловушка на собеседованиях; для точной проверки используйте `x === null`.

## Чем `==` отличается от `===`?

`===` сравнивает значения и типы без приведения. `==` перед сравнением приводит операнды к одному типу по таблице правил.

```ts
1 == "1";        // true — строка приведена к числу
null == undefined; // true — единственное равенство для null
NaN == NaN;      // false — NaN не равен ничему, даже себе
```

На практике всегда используйте `===`, кроме идиомы `x == null`, проверяющей сразу `null` и `undefined`.

## Чем `null` отличается от `undefined`?

`undefined` — «значение не задано»: переменная объявлена, но не инициализирована, свойство отсутствует, функция ничего не вернула. `null` — «значение намеренно пустое», его назначает сам разработчик.

```ts
let a;            // undefined
const b = null;   // явно положили «пусто»
```

По умолчанию всё «незаполненное» — `undefined`; `null` — осознанный маркер отсутствия объекта.

## Что такое NaN и как его проверить?

`NaN` (Not-a-Number) — специальное значение `number`, результат неудачной числовой операции. Оно не равно ничему, включая себя, поэтому `x === NaN` всегда `false`.

```ts
NaN === NaN;              // false
Number("abc");            // NaN
Number.isNaN(Number("abc")); // true — корректная проверка
```

Современный способ проверки — `Number.isNaN(x)`. Глобальный `isNaN(x)` сначала приводит аргумент к числу, что даёт сюрпризы: `isNaN("abc") === true`, но и `Number.isNaN("abc") === false`.

## Почему `0.1 + 0.2 !== 0.3`?

Числа в JavaScript хранятся в формате IEEE 754 double precision (64 бита), где многие десятичные дроби не представимы точно в двоичной системе. `0.1` и `0.2` округляются при записи, сумма даёт `0.30000000000000004`.

```ts
0.1 + 0.2 === 0.3;             // false
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true — правильное сравнение
```

Для денег либо считайте в копейках целыми числами, либо сравнивайте с допуском (`epsilon`).

## Как работает приведение типов (toPrimitive)?

Когда объект оказывается в контексте, где нужно примитивное значение, движок вызывает `Symbol.toPrimitive`, затем `valueOf` и `toString` — состав зависит от hint: `default`, `number` или `string`.

```ts
const obj = {
  valueOf() { return 42; },
  toString() { return "сорок два"; },
};
obj * 2;      // 84 — number hint
`${obj}`;     // "сорок два" — string hint
```

Знание этого механизма объясняет, почему `[] + []` даёт пустую строку, а `[] + {}` — `"[object Object]"`.

## Чем `var` отличается от `let` и `const`?

`var` имеет функциональную область видимости и поднимается (hoisting) со значением `undefined`; `let`/`const` — блочную область видимости и временную мёртвую зону (TDZ) до объявления.

```ts
console.log(a); // undefined (var поднялся)
var a = 1;
console.log(b); // ReferenceError (TDZ)
let b = 2;
```

`const` запрещает переприсваивание переменной, но не делает объекты иммутабельными: содержимое объекта менять можно. Современный стандарт: `const` по умолчанию, `let` при необходимости переприсваивания, `var` — не использовать.

## Что такое шаблонные строки и чем они лучше конкатенации?

Шаблонные строки (backticks) поддерживают интерполяцию `${}`, многострочность и тегированные шаблоны. Они читаются лучше конкатенации через `+` и позволяют встраивать выражения целиком.

```ts
const name = "Мир";
const msg = `Привет, ${name.toUpperCase()}!
Сегодня ${new Date().getFullYear()} год`;
```

Тегированные шаблоны (`tag\`...\``) применяют функцию к частям строки — так работают styled-components и GraphQL-запросы.
