# Основы и ООП

## Что такое JDK, JRE и JVM?

JVM — виртуальная машина, исполняющая байткод: независимость от платформы, JIT-компиляция, управление памятью. JRE = JVM + стандартная библиотека (среда выполнения). JDK = JRE + инструменты разработчика (javac, javadoc, jdb).

```
JDK ⊃ JRE ⊃ JVM
```

Разделение объясняет главный слоган Java «write once, run anywhere»: компилятор JDK пишет платформенно-независимый байткод, а JVM каждой платформы его исполняет.

## Какие принципы ООП и как они выглядят в Java?

Инкапсуляция — скрытие состояния за методами (`private` поля + геттеры). Наследование — `extends`: переиспользование и специализация. Полиморфизм — один интерфейс, разные реализации: выбор метода по фактическому типу в рантайме. Абстракция — `abstract`/`interface`: контракт без реализации.

```java
interface Payment { void pay(int amount); }

class CardPayment implements Payment {
    public void pay(int amount) { /* … */ }
}

Payment p = new CardPayment(); // полиморфизм: работаем через контракт
p.pay(100);
```

На собеседовании про «четвёртый принцип» (абстракцию) обычно уточняют разницу с инкапсуляцией: абстракция — про «что делаем», инкапсуляция — про «как прячем».

## Чем перегрузка отличается от переопределения?

Перегрузка (overload) — несколько методов с одним именем и разными сигнатурами в одном классе; разрешается компилятором. Переопределение (override) — замена реализации метода родителя с той же сигнатурой; разрешается в рантайме.

```java
class Shape {
    double area() { return 0; }
    double area(double scale) { return area() * scale; } // перегрузка
}

class Circle extends Shape {
    @Override
    double area() { return Math.PI * r * r; } // переопределение
}
```

`@Override` обязателен по конвенции: ловит опечатки в сигнатуре, которые иначе превращаются в перегрузку.

## Чем абстрактный класс отличается от интерфейса?

Абстрактный класс — «кто это»: может иметь состояние (поля), конструктор, реализации методов; наследуется один раз. Интерфейс — «что умеет»: констант и default-методов, полей состояния нет; реализуется многократно.

```java
abstract class Vehicle {
    protected int speed;              // состояние
    abstract void accelerate();       // нет реализации
    void stop() { speed = 0; }        // общая логика
}

interface Drivable { void drive(); }
class Car extends Vehicle implements Drivable { … }
```

Правило: интерфейс — для контрактов способностей (`Comparable`, `Serializable`), абстрактный класс — для общего каркаса иерархии.

## Зачем переопределять equals и hashCode вместе?

Контракт: равные объекты обязаны иметь равные хеш-коды. `equals` без `hashCode` ломает HashMap/HashSet: равные объекты попадают в разные корзины и «не находятся».

```java
class Point {
    int x, y;

    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point p)) return false;
        return x == p.x && y == p.y;
    }
    public int hashCode() { return Objects.hash(x, y); }
}
```

По умолчанию `equals` сравнивает ссылки. Класс с value-семантикой (ключи мапы, элементы множества) без пары методов — баг в коллекциях.

## Почему String иммутабельна и что такое String pool?

Строка — неизменяемый объект: операции создают новые. Пул строк переиспользует литералы; одинаковые литералы — один объект.

```java
String a = "hi";
String b = "hi";
a == b;              // true — один объект из пула

String c = new String("hi");
a == c;              // false — явный new вне пула
a.equals(c);         // true — сравнение по значению
```

Иммутабельность даёт потокобезопасность, безопасное кеширование hashcode и ключей HashMap. Для конкатенации в цикле — StringBuilder, иначе каждая итерация плодит новые строки.

## Что делают static и final?

`static` — принадлежит классу, а не экземпляру: общее поле для всех объектов, вызов без создания. `final` — «нельзя менять»: поле — константа, метод — нельзя переопределить, класс — нельзя наследовать.

```java
class Config {
    static final int MAX = 100;  // константа класса
    static int counter;           // общее состояние
    final String id;              // присваивается один раз (в конструкторе)
}
```

`static`-контекст не видит `this`: нельзя обращаться к полям экземпляра. final-поля примитивов/ссылок — но объект за final-ссылкой менять можно.

## Что такое record и зачем он?

Record (Java 16+) — компактный класс-носитель данных: поля, конструктор, `equals/hashCode/toString` генерируются компилятором.

```java
record Point(int x, int y) {}

Point p = new Point(1, 2);
p.x();          // аксессор
p.equals(new Point(1, 2)); // true — value-семантика из коробки
```

Заменяет «POJO с двадцатью строками boilerplate» для DTO и value-объектов. Иммутабелен по дизайну; для JPA-сущностей и мутабельных моделей по-прежнему обычные классы.
