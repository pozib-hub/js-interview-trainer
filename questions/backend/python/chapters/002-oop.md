# ООП и магические методы

## Как устроены классы и __init__?

`__init__` — инициализатор экземпляра (не конструктор — им является `__new__`): вызывается после создания объекта, заполняет атрибуты.

```python
class User:
    def __init__(self, name: str, age: int = 0):
        self.name = name    # атрибуты создаются здесь
        self.age = age

    def greet(self) -> str:
        return f"Я {self.name}"

u = User("Аня", 30)
```

`self` — явная ссылка на экземпляр: у Python нет скрытого this. Атрибут можно добавить и снаружи (`u.x = 1`), но это делает контракт класса менее очевидным.

## Что такое @property?

Дескриптор, превращающий метод в вычисляемый атрибут: доступ как к полю, логика внутри. Setter — с валидацией.

```python
class Circle:
    def __init__(self, r):
        self._r = r

    @property
    def area(self):
        return 3.14159 * self._r ** 2

    @property
    def radius(self): return self._r

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("радиус должен быть > 0")
        self._r = value
```

Польза: инкапсуляция без getX/setX, обратная совместимость при переходе от поля к вычислению.

## Что такое dunder-методы и какие главные?

«Double underscore»-методы — протоколы языка: `__str__`/`__repr__` — текстовое представление, `__eq__`/`__hash__` — сравнение, `__len__`, `__iter__`, `__getitem__` — протокол коллекции.

```python
class Money:
    def __init__(self, rub): self.rub = rub
    def __repr__(self): return f"Money({self.rub})"
    def __str__(self): return f"{self.rub} ₽"
    def __eq__(self, other): return self.rub == other.rub
    def __add__(self, other): return Money(self.rub + other.rub)

print(Money(100) + Money(50))  # 150 ₽
```

Dunder-методы вызываются синтаксисом языка (`+`, `len()`, `for`) — это способ встроить свои типы в синтаксис Python.

## Как работает наследование и MRO?

Python поддерживает множественное наследование; порядок разрешения методов — MRO (Method Resolution Order) по алгоритму C3: слева направо, без повторов, родитель после потомка.

```python
class A:
    def hello(self): print("A")

class B(A):
    def hello(self): print("B"); super().hello()

class C(A):
    def hello(self): print("C"); super().hello()

class D(B, C): pass

D().hello()  # B → C → A — MRO: D, B, C, A
D.__mro__    # можно посмотреть
```

`super()` идёт по MRO, а не «к родителю». Множественное наследование оправдано для миксинов; для иерархий «is-a» — single inheritance.

## Что такое dataclasses?

Декоратор `@dataclass` генерирует `__init__`, `__repr__`, `__eq__` по аннотациям полей: data-класс в 5 строк вместо 30.

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)  # immutability + hashable
class Point:
    x: float
    y: float = 0.0
    tags: list[str] = field(default_factory=list)  # не мутируемый дефолт!

p = Point(1, 2)
p == Point(1, 2)  # True
```

`frozen=True` — иммутабельность и хешируемость (dict key). `default_factory` — правильный mutable-дефолт. Для валидации полей — pydantic-модели.

## Чем classmethod отличается от staticmethod?

`@classmethod` получает класс (`cls`) — фабричные методы и доступ к классовым атрибутам. `@staticmethod` — просто функция внутри пространства имён класса.

```python
class Date:
    def __init__(self, y, m, d): ...

    @classmethod
    def from_iso(cls, s: str):        # альтернативный конструктор
        y, m, d = s.split("-")
        return cls(int(y), int(m), int(d))

    @staticmethod
    def is_leap(year: int) -> bool:   # утилита без доступа к классу
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

Date.from_iso("2026-10-30")
```

Фабрика через classmethod корректно работает в наследниках: `cls(...)` создаст подкласс, а не захардкоженный Date.

## Что такое __repr__ и __str__ и когда какой вызывается?

`__repr__` — однозначное представление для разработчика (логи, REPL, отладка), `__str__` — читаемое для пользователя (print). Если `__str__` нет — используется `__repr__`.

```python
class User:
    def __repr__(self):
        return f"User(id={self.id!r}, name={self.name!r})"  # можно воссоздать
    def __str__(self):
        return self.name

repr(user)  # "User(id=1, name='Аня')"
str(user)    # "Аня"
```

Правило: `__repr__` обязателен для всех своих классов (незаменим в логах), `__str__` — если пользователю нужно видеть объект иначе.

## Как работает duck typing и Protocols?

«Если оно ходит как утка…» — важен не тип, а наличие методов. Формализация — `typing.Protocol`: структурная проверка «есть нужные методы» без наследования.

```python
class Closeable(Protocol):
    def close(self) -> None: ...

def process(res: Closeable):  # любой объект с .close()
    ...
    res.close()

class DbConn:                 # не наследует Protocol!
    def close(self): ...

process(DbConn())  # ok — структурно совместим
```

Protocol даёт статическим анализаторам проверить duck typing заранее, вместо ошибок в рантайме.
