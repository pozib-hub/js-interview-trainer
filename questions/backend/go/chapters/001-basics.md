# Основы Go

## Почему Go выбирают для серверной разработки?

Компиляция в один статический бинарник, низкий порог вхождения, быстрая сборка и запуск, встроенный профайлер и инструментарий, горутины для конкурентности. Из «медленных» мест — относительно многословная обработка ошибок.

```go
// Один файл → деплой: без рантайма, зависимостей и интерпретатора
package main

func main() {
    http.ListenAndServe(":8080", nil)
}
```

Типовые ниши Go: микросервисы, сетевые утилиты, CLI, инфраструктурные инструменты (Docker, Kubernetes написаны на Go).

## Какие базовые типы в Go и что такое zero value?

Типы: `int`, `uint`, `float64`, `bool`, `string`, `byte`, `rune`, слайсы, map, структуры, указатели. Любая переменная без явной инициализации получает zero value: 0, "", false, nil, пустая структура.

```go
var i int      // 0
var s string   // ""
var p *int     // nil
var m map[string]int // nil
```

Zero value — часть контракта языка: новые поля структур не ломают старые данные. Отсюда же идиома `if s == ""` вместо проверки на null-строку.

## Чем слайс отличается от массива?

Массив `[N]T` — фиксированный размер, часть типа, значение копируется целиком. Слайс `[]T` — заголовок с указателем на массив, длиной и capacity; передаётся дёшево, растёт через `append`.

```go
arr := [3]int{1, 2, 3}
s := []int{1, 2, 3}
s = append(s, 4)      // может реаллоцировать
s2 := s[:2]           // разделяет память с s
```

Главная ловушка — шаринг памяти: два слайса от одного массива видят изменения друг друга, а `append` за capacity создаёт независимую копию.

## Как устроены map в Go?

`map[K]V` — хеш-таблица. Неупорядочена: порядок обхода рандомизирован. Чтение отсутствующего ключа даёт zero value; запись в nil-мапу паникует.

```go
m := make(map[string]int)
v, ok := m["key"]  // идиома "comma ok"
if !ok { /* ключа нет */ }
delete(m, "key")
```

Map — не потокобезопасна: для конкурентного доступа нужен `sync.Mutex` или `sync.Map`. Key должен быть сравнимым (слайсы и мапы — нельзя).

## Что такое rune и почему строка не индексируется «по буквам»?

Строка в Go — байтовый слайс в UTF-8. `s[i]` — байт, не символ. Rune — кодовая точка Unicode (int32).

```go
s := "привет"
len(s)               // 12 — байты!
utf8.RuneCountInString(s) // 6 — символы
for i, r := range s {}    // i — байтовый индекс, r — rune
```

Индексы по байтам ломаются на не-ASCII — отсюда `[]rune(s)` для посимвольной работы и пакет `strings`/`unicode/utf8`.

## Что делает defer?

Откладывает вызов функции до выхода из текущей функции (в порядке LIFO). Аргументы вычисляются сразу, вызов — потом.

```go
func read() error {
    f, err := os.Open("file")
    if err != nil { return err }
    defer f.Close() // закроется при любом return

    defer fmt.Println("first")
    defer fmt.Println("second") // выполнится раньше first
    return nil
}
```

defer в цикле накапливает отложенные вызовы до конца функции — ресурсы стоит освобождать в отдельной функции или сразу.

## Зачем в Go указатели?

Передача по значению копирует данные — для структур это дорого и мутирует копию. Указатель позволяет разделить одну структуру и изменить её.

```go
type User struct{ Name string }

func rename(u *User, n string) { u.Name = n } // мутация оригинала

u := User{Name: "Ivan"}
rename(&u, "Petr")
```

У Go нет арифметики указателей; разыменование безопаснее, чем в C. Приём-маркер на собеседовании: «всё в Go передаётся по значению, просто у slice/map/chan само значение — маленький заголовок со ссылкой».

## Почему в Go ошибки — это значения?

Ошибка — обычное значение типа `error` (интерфейс с методом `Error() string`), которое возвращают явно, без исключений. Это делает путь ошибок видимым в сигнатуре и обязывает обработать.

```go
f, err := os.Open("config.json")
if err != nil {
    return fmt.Errorf("открываю конфиг: %w", err)
}
```

Обёртка `%w` сохраняет исходную ошибку для `errors.Is/As`. Паника — для непоправимых программных ошибок, не для ожидаемых отказов.
