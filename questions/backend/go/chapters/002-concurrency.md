# Горутины и каналы

## Что такое горутина?

Легковесный поток выполнения, запускаемый словом `go`. Стартует на нескольких килобайтах стека (растёт по мере надобности), переключение — в рантайме Go, а не через ОС-потоки.

```go
go processOrder(order) // запустили и пошли дальше
```

Миллион горутин — рабочий сценарий. Цена — у горутин нет ID и прямого контроля: «убить» чужую горутину нельзя, только договориться (context, каналы).

## Что такое канал и какие они бывают?

Канал — типизированный канал связи между горутинами: передача значения с синхронизацией. Буферизованный (`make(chan T, n)`) копит n значений без читателя; небуферизованный блокирует отправителя до появления получателя.

```go
ch := make(chan int)        // небуферизованный: handoff
ch := make(chan int, 10)    // буфер: очередь на 10

ch <- 42   // отправить
v := <-ch  // получить
```

Идиома Go: «не общайтесь через разделяемую память, разделяйте память через общение».

## Как работает select?

select ждёт несколько канальных операций одновременно и выполняет первую готовую (при готовности нескольких — случайную). С `default` — неблокирующая попытка.

```go
select {
case v := <-results:
    process(v)
case <-timeout:
    return errors.New("таймаут")
}
```

Это строительный блок таймаутов, отмен и мультиплексирования. `for { select {...} }` — стандартный цикл воркера.

## Что происходит при чтении/записи в закрытый или nil канал?

Три состояния — таблица поведения: закрытый: отправка паникует, чтение сразу возвращает zero value + `ok == false`. nil: и чтение, и запись блокируются навсегда.

```go
ch := make(chan int)
close(ch)

v, ok := <-ch  // 0, false — drain
ch <- 1        // panic: send on closed channel
```

Закрывать канал должен отправитель, и только когда больше никто не будет слать. Приёмник о закрытии узнаёт через `v, ok := <-ch` или `for v := range ch`.

## Для чего закрывают каналы и как устроен range?

`close` — сигнал «значений больше не будет». `for v := range ch` читает, пока канал не закрыт, и завершает цикл.

```go
func producer(out chan<- int) {
    for i := 0; i < 5; i++ { out <- i }
    close(out) // сигнал: всё
}

for v := range ch { // выйдет сам после close
    process(v)
}
```

Ошибка новичка — закрывать канал со стороны получателя или закрывать дважды (вторая — паника).

## Что такое worker pool?

Фиксированный набор горутин-воркеров, читающих задачи из общего канала: ограничивает параллелизм и переиспользует горутины.

```go
jobs := make(chan Job, 100)
var wg sync.WaitGroup

for i := 0; i < 8; i++ { // 8 воркеров
    wg.Add(1)
    go func() {
        defer wg.Done()
        for job := range jobs { process(job) }
    }()
}

// накормить и закрыть
close(jobs)
wg.Wait()
```

Так ограничивают нагрузку на БД/внешний API: не 10 000 горутин, а N параллельных соединений.

## Зачем sync.WaitGroup и как им пользоваться?

WaitGroup — счётчик горутин: `Add(n)` до старта, `Done()` в конце каждой (обычно через defer), `Wait()` блокирует до обнуления.

```go
var wg sync.WaitGroup
for _, u := range users {
    wg.Add(1)
    go func(id string) {
        defer wg.Done()
        enrich(id)
    }(u.ID)
}
wg.Wait()
```

Ловушки: `Add` внутри горутины — гонка с `Wait`; копирование WaitGroup (всегда через указатель/замыкание).

## Что такое context и зачем он нужен?

`context.Context` — стандартный способ передать отмену, дедлайн и запрос-скопенные значения через слои вызовов.

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

select {
case <-ctx.Done():
    return ctx.Err() // deadline exceeded / canceled
case res := <-work:
    return res
}
```

Правила: контекст — первый аргумент функции; не хранят в структурах; значения — только для «прозрачных» метаданных (trace id), не для бизнес-параметров. `http.Request` в Go несёт контекст с отменой при обрыве соединения — ручной `{}` вместо него теряет отмену.
