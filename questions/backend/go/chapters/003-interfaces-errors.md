# Интерфейсы и ошибки

## Как работает неявная реализация интерфейсов?

Тип удовлетворяет интерфейсу, если имеет все его методы — без `implements`. Это structural typing: интерфейс и реализация не знают друг о друге.

```go
type Sayer interface{ Say() string }

type Dog struct{}
func (d Dog) Say() string { return "Гав" }

var s Sayer = Dog{} // Dog реализует Sayer неявно
```

Следствие: интерфейсы можно объявлять там, где они используются (consumer-side), включая тестовые — для моков не нужно трогать прод-код.

## Что такое пустой интерфейс interface{} и any?

`interface{}` (= `any` с Go 1.18) не требует ни одного метода — подходит любой тип. Это escape hatch динамической типизации.

```go
func print(v any) { fmt.Println(v) }

// type switch — способ узнать, что внутри
switch x := v.(type) {
case int:    …
case string: …
}
```

До дженериков им злоупотребляли для коллекций «чего угодно». Теперь правило: `any` — на границах (JSON, логирование), в доменной логике — конкретные типы.

## Что такое композиция интерфейсов?

Маленькие интерфейсы собираются в большие через встраивание. Стандартная библиотека построена на микро-интерфейсах.

```go
type Reader interface { Read(p []byte) (int, error) }
type Writer interface { Write(p []byte) (int, error) }
type ReadWriter interface { // композит
    Reader
    Writer
}
```

Идиома Go: «интерфейс тем лучше, чем меньше». Одно-двухметодные интерфейсы (`io.Reader`, `io.Writer`) дают максимум гибкости: реализовать можно почти всё.

## Как устроено значение интерфейса внутри?

Интерфейс — пара (тип, значение): динамическая информация о конкретном типе и данные. Отсюда поведение nil-ловушки.

```go
var p *MyErr = nil
var err error = p    // интерфейс != nil!
err != nil           // true: тип внутри есть (*MyErr), значение nil
```

Классический баг: функция возвращает конкретный nil-указатель как error, а вызывающий проверяет `err != nil` — true. Лечится возвратом `nil` явно, а не типизированной переменной.

## Чем errors.Is отличается от errors.As и As от прямого приведения?

`errors.Is` — сравнение с конкретным значением-эталоном по цепочке (`== `или через `Is()`-метод). `errors.As` — извлечение ошибки нужного типа в переменную.

```go
if errors.Is(err, os.ErrNotExist) { /* файла нет */ }

var pathErr *os.PathError
if errors.As(err, &pathErr) { log(pathErr.Path) }
```

Оба работают сквозь обёртки `%w`. Прямое приведение `err.(*MyErr)` видит только верхний слой обёртки и не находит завернутые ошибки.

## Что такое wrapping ошибок и зачем он нужен?

Оборачивание добавляет контекст к ошибке, сохраняя оригинал: `fmt.Errorf("читаю конфиг %s: %w", path, err)`.

```go
func loadConfig() error {
    data, err := os.ReadFile(path)
    if err != nil {
        return fmt.Errorf("load config %q: %w", path, err)
    }
    …
}
// caller: errors.Is(err, fs.ErrNotExist) — найдёт через оба слоя
```

Один раз добавив `%w`, сохраняете всю цепочку для верхних уровней: и человек читает контекст, и код может программно проверить причину (`os.ErrNotExist`, `sql.ErrNoRows`).

## Когда паниковать, а когда возвращать ошибку?

Ошибка — ожидаемый отказ (файл не найден, таймаут, невалидный ввод): часть контракта. Паника — неисправимая программная ошибка (инвариант сломан, невозможное состояние).

```go
// Ошибка: пользователь вводит мусор — это норма
func Parse(s string) (Config, error) { … }

// Паника: нарушили контракт библиотеки
func MustCompile(re string) *Regexp {
    r, err := Compile(re)
    if err != nil { panic(err) }
    return r
}
```

Панику не ловят для «управления потоком»; recover — только на границах (HTTP-хендлер, чтобы не уронить сервер). Ожидаемое — error, сломанное — panic.

## Как определять свои типы ошибок?

Тип с методом `Error() string`. Современный способ — sentinel-ошибки-значения или структурные ошибки с полями, совместимые с `Is/As`.

```go
var ErrNotFound = errors.New("not found")

type ValidationError struct {
    Field string
    Cause string
}

func (e *ValidationError) Error() string {
    return e.Field + ": " + e.Cause
}

// вызывающий:
var ve *ValidationError
if errors.As(err, &ve) { highlight(ve.Field) }
```

Пакет `errors` (Is/As/Unwrap) делает самодельные типы полноценными участниками цепочек: сравнение по типу и значениям работает сквозь обёртки.
