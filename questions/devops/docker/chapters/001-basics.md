# Основы Docker

## Что такое контейнер и чем он отличается от виртуальной машины?

Контейнер изолирует приложение на уровне ОС через namespaces и cgroups ядра Linux, разделяя ядро с хостом. ВМ эмулирует железо и запускает полноценную гостевую ОС со своим ядром.

```
Контейнер: приложение + библиотеки | общее ядро хоста
ВМ:        приложение + библиотеки + гостевая ОС | гипервизор
```

Отсюда разница: контейнеры стартуют за секунды, весят мегабайты, дешевле по памяти; ВМ дают полную изоляцию и любые ОС, но тяжелее. На macOS/Windows Docker внутри запускает Linux-ВМ — контейнеры всегда Linux.

## Что такое образ и что такое контейнер?

Образ — неизменяемый шаблон: слои файловой системы + метаданные. Контейнер — запущенный экземпляр образа: поверх слоёв образа добавляется writable-слой для изменений.

```bash
docker build -t myapp:1.0 .   # образ из Dockerfile
docker run myapp:1.0          # контейнер из образа
docker ps                     # запущенные контейнеры
docker images                  # локальные образы
```

Один образ → много контейнеров; удаление контейнера не трогает образ; изменения внутри контейнера (без volume) пропадают с его удалением.

## Из чего состоит Dockerfile и что делает каждая инструкция?

Dockerfile — рецепт сборки образа по шагам. `FROM` — базовый образ, `COPY` — файлы внутрь, `RUN` — команды сборки, `ENV` — переменные, `EXPOSE` — документация порта, `CMD`/`ENTRYPOINT` — что запускать.

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
```

Каждая инструкция создаёт слой; слои кешируются — порядок инструкций критичен для скорости сборки (сначала зависимости, потом код).

## Чем ENTRYPOINT отличается от CMD?

`CMD` — аргументы по умолчанию, легко переопределяются в `docker run`. `ENTRYPOINT` — фиксированная команда: аргументы docker run добавляются к ней, а не заменяют.

```dockerfile
# Приём «исполняемый контейнер»:
ENTRYPOINT ["node", "server.js"]
CMD ["--port", "3000"]
```

```bash
docker run myapp                    # node server.js --port 3000
docker run myapp --port 8080       # node server.js --port 8080 (CMD заменён)
docker run --entrypoint sh myapp   # переопределение для отладки
```

Идиома: ENTRYPOINT задаёт «что за программа», CMD — «дефолтные настройки». Для утилит-контейнеров — только ENTRYPOINT; для гибких образов — только CMD.

## Что такое тома (volumes) и зачем они?

Слои контейнера эфемерны: данные нужно выносить наружу. Volume — хранилище, управляемое Docker'ом; bind mount — проброс каталога хоста.

```bash
docker volume create pgdata
docker run -v pgdata:/var/lib/postgresql/data postgres

docker run -v $(pwd)/src:/app/src myapp   # bind mount — код на разработке
```

Volume переживают контейнеры, легко бекапятся, работают на всех ОС (bind с macOS медленнее из-за прослойки файловой системы ВМ).

## Как работают сети Docker?

Bridge (default) — приватная сеть с NAT: контейнеры друг друга видят по имени (в рамках user-defined сети), наружу ходят через SNAT. Host — сетевой стек хоста без изоляции. None — без сети.

```bash
docker network create mynet
docker run -d --name db --network mynet postgres
docker run --network mynet myapp
# внутри myapp: postgres://db:5432 — имя контейнера резолвится
```

Классика отладки: `docker run --network container:app alpine` — «залезть в сеть» контейнера с утилитами без изменений образа.

## Как опубликовать порты и почему 0.0.0.0?

`-p HOST:CONTAINER` пробрасывает порт контейнера на хост. Формат `IP:HOST:CONTAINER` управляет, на каком интерфейсе хоста слушать.

```bash
docker run -p 8080:3000 myapp      # хост:8080 → контейнер:3000
docker run -p 127.0.0.1:5432:5432 postgres  # только localhost
```

Публикация на 0.0.0.0 (по умолчанию `-p 8080:3000`) открывает порт на ВСЕХ интерфейсах, включая внешний IP — СУБД так светить опасно. Для dev — 127.0.0.1, для продакшена — за реверс-прокси или в приватной сети.

## Как зайти внутрь запущенного контейнера и посмотреть логи?

```bash
docker exec -it app sh          # shell внутри контейнера (sh — alpine без bash)
docker exec -it app ls /app     # разовая команда
docker logs -f --tail 100 app   # логи stdout/stderr, follow
docker inspect app              # все метаданные (IP, env, mounts)
docker stats                    # потребление ресурсов в реальном времени
```

`exec` не запускает новый контейнер — добавляет процесс в существующий. Если в образе нет shell (distroless) — exec sh невозможен: логи и healthcheck — единственное окно.
